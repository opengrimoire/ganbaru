The need (from milestone 9 step 4): Chat folder grant and scratch approval overrides are register groups ranked by a static revocation-wins priority, with "inherit" (no override) ranked least strict. At runtime an inherited value resolves through the channel override and then the teammate's behavior, so it can be stricter than an explicit value. When device A clears an override (inherit, resolving to `ask`) while device B sets `unattended`, B wins and the folder runs looser than A intended. A static rank cannot know the resolved value. The Chat hook cannot fix it today because (a) the hook receives only the connection, table, changed keys, and a change sink, never the concurrent losing versions of a group, and conflicts are recorded only for surfaced groups; (b) a hook cannot write a captured edit, since capture triggers stand down during apply and forcing a group needs the engine.

Deliver the smallest general engine shape that lets a domain resolve such a case deterministically on every device, for example:
1. A hook context (an extension of `MaterializeHook` or a new optional method, keeping existing hooks compiling unchanged) that, for each changed key, can read the concurrent versions of named register groups that the latest merge decided, including non-surfaced groups: each version's decoded value, clock, and writer, and which one won.
2. A way for the hook to settle a group with a value: written as an ordinary captured local change of that group (sealed by the device like a user edit, causally after the versions it saw), so every device that runs the same deterministic rule writes the same value and the result converges, with no apply failure and no conflict ping-pong. Equal values written by several devices must converge quietly (sealing already skips a group whose value equals the current winner; check concurrent equal writes).
Alternatives are fine if they are simpler and equally general (for example a context-aware priority callback), as long as they are deterministic across devices, never fail apply, and work when the losing version is elided or compacted (hydrate as winner elision requires).
