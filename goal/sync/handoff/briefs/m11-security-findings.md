# Milestone 11 package security review findings (a3d32e6a)

## Formats and wire: merge with follow-ups
1. Low/Medium: `crates/ganbaru-sync/src/authorization.rs` `AuthState::check` (~200-290) does not refuse a proposal hash already in the selected chain nor check freshness; only the anchor's `Engine::sequence` dedupes. A compromised anchor (or one without admin key, for example after a forced handover) can replay an old signed `SetRole Recovery` after a kit rotation (reinstating a leaked kit) or an old `SetRole Device Admin` (repromoting a demoted admin). Fix: keep selected proposal hashes in selection state (insert_entry already stores proposal_hash) and refuse duplicates in `check`.
2. Low: `crates/ganbaru-sync-replica/src/writer.rs:381` `read_record` uses plain `std::fs::read`; use `read_regular_file_capped(.., FinalSymlink::Refuse)` like other device-local files.
Note: `PersonKeyRelease` sends the person private key to linked devices over TLS (design; keys area to confirm).
Summary: Sync formats sign every field that matters under separate signature domains, bind the vault space into every operation and proposal, and decode untrusted peer input with bounded, canonical parsers that refuse trailing bytes and older certificate versions. Handoff protocol 15 frames are size-capped and validated, sync requests are tied to the pinned TLS certificate, and device-local sync files are read with size caps and symlink refusal and written atomically with owner-only permissions.

## Keys and Keystore: merge with follow-ups (Medium fix before acceptance; we fix before landing)
3. Medium (cross-area): a device removed through the log (by a non-hub admin or the anchor desktop) stays linked in the coordinator's pairing, so `release_person_key` (`app/src/vault/handoff/coordinator.rs:362-370`), `verify_authenticated_peer`, and `transport/server/dispatch.rs:416-430` (`PersonKeyRequest`, `DownloadBundle`) still serve it the person key and whole-vault bundles; `reconcile_devices` (`sync/service.rs:2697-2790`) maps unlink to removal but not the reverse. Fix: when the coordinator applies a log removal, unlink that device's pairing entry; refuse `ReleasePersonKey` and `DownloadBundle` (and any other coordinator service, including hub pulls) for a device the selected log removed; test removal by a non-hub admin followed by a person key request and a bundle download.
4. Low: Reset sync state (`crates/ganbaru-sync-replica/src/reset.rs`) keeps the device key, admin key, and pending recovery seed, so it is not a compromise remedy. Fix: say so in Settings and `docs/data/sync.md` (~105), or rotate keys on reset.
5. Low: `own_is_admin` in `app/src/sync/authority.rs` calls `ensure_admin_key` from a read model, creating keyring admin keys on unpromoted devices when Settings opens. Fix: read without creating.
6. Low: stale sentences in `docs/data/security/network-and-privacy.md` lines ~70, ~72, ~74 (Android keys in private files until Keystore wrapping; settings confirmation lands with the authority UI). Rewrite to match sync.md.
Design notes (document, no fix): a recovery kit key is a full admin; Android Keystore keys have no user-auth requirement so a stolen booted phone can use them (removal plus quarantine is the answer); any admin can set the anchor's admin key to another key.
Summary: Sync, linking, and person keys live in the OS keyring on desktop and in files sealed by Android Keystore on Android; loss is tracked per key reference, keys are never logged, and recovery kit codes are redacted from debug output and errors. Reset sync state keeps the device and admin keys, so a compromised device is answered by removal and quarantine.

## Authority, store gate, exclusion: fix first
7. Critical: a former admin can rewrite the log from the past. `crates/ganbaru-sync/src/authorization.rs` ~200-215 (`AuthState::check` handover branch), `rank` ~325, `crates/ganbaru-sync/src/exclusion.rs` ~733 (`record_excluded_entries`). A demoted or removed admin (or stolen admin laptop with its admin key) seals a handover to itself continuing from a revision where it was still admin (checked only against that parent state), chains self-handovers past the honest epoch (selection ranks epoch first, so the branch wins everywhere), its excluded operations' carried entries still count for selection (removed) or its writers stay active (demoted); as anchor it removes every honest device with cutoff 0 and can replace the recovery key. Recovery-key handovers only start an epoch race it can always extend. Suggested fix: reject a handover when any stored descendant of its parent removes or demotes its author or target, or replaces the recovery key it uses; do not count entries carried by a removed device's writers beyond the recorded cutoffs.
8. High (same as 3): the coordinator admits sync peers by pairing state and quarantine only (`app/src/vault/handoff/transport/server/dispatch.rs` ~217-270, `crates/ganbaru-sync-replica/src/hub.rs` `respond_inner` ~301, `sync/service.rs` 2704-2780); a device removed in the log by another admin keeps pulling every operation and asset and can request a whole-vault refresh. Fix: admit only devices the selected log enrolls and has not removed (as member admission does), and unlink pairing peers the log removed.
9. Medium: `crates/ganbaru-sync-replica/src/client.rs` ~700-712 and `service.rs` ~1396: `replay_outbox` settles any final rejection from the coordinator hub; a compromised non-anchor coordinator answers `DeviceRemoved` to a proposal removing it and the outbox drops it. Fix: final only when the answering peer is the log's anchor (or the answer carries the anchor's signature); else keep waiting. (Verify against part A's claim that a coordinator relays only rejections from the anchor.)
10. Medium: `crates/ganbaru-sync/src/store.rs` `store_genesis` Removed branch (~330): a removed device mints up to 64 writers with cutoff 0, each with up to 1,024 excluded operations of up to 512 KiB (about 32 GiB), stored and forwarded everywhere. Fix: bound excluded storage per removed device, or refuse geneses of writers the cutoffs do not name.
11. Low: `authorization.rs` `removal_cutoffs` ~1200 trusts the coordinator's covered vector; a compromised coordinator reports u64::MAX so removal never excludes. Fix: clamp to what the anchor verified plus bounded slack.

## Listener surface review (a3d32e6a): merge with follow-ups

12. Medium (privacy): any LAN host that connects receives a member's stable server certificate (TLS 1.3 sends it before client auth aborts), whose common name carries the device id (`apps/client/src-tauri/app/src/vault/handoff/transport/server/member.rs:73`, `crates/ganbaru-handoff/src/pairing.rs:1144-1148`). Links hourly advertisements and networks; a removed device keeps every member fingerprint; the mDNS host name is fixed per app run, defeating hourly tag rotation. `network-and-privacy.md:20` ("not the device name, the vault, or the certificate, and cannot link one hour's advertisement to the next") is false. Fix: drop the device id from the common name (no external users, repinning fine), rotate the mDNS host name with each hourly tag, correct `network-and-privacy.md:20` and `milestone_11.md:127` wording in docs. Membership proof before the server certificate is a recorded follow-up.
13. Low: one admitted member can take all 64 authenticated connections (`server/limits.rs:205`). Fix: per-source authenticated cap using the existing `SourceKey`.
14. Low: reported endpoint poisoning (`apps/client/src-tauri/app/src/sync/peers.rs:56-58`, `crates/ganbaru-sync-replica/src/peers/book.rs:206`): `observe_reported` trims before `retain_members`; fake device ids evict real second-hand endpoints; 8 attacker addresses for a real device cost ~80 s per peer. Fix: filter reported entries to live members before trimming; order second-hand after first-hand endpoints; shorter connect timeout for member dials.
15. Low: a spoofed mDNS record replaces a member's known endpoints (`crates/ganbaru-sync-replica/src/peers/plan.rs:114`). Fix: append the book's endpoints after discovered ones.
16. Low (needs admin): enrollment does not reject a reused TLS fingerprint (`crates/ganbaru-sync/src/authorization.rs:229` checks only device id); decoy enroll then remove makes member X refused as Removed. Fix: reject enrollment of a fingerprint already in the log, including removed devices.

Listener reviewer summary text (use after finding 12 is fixed, adjust to the fixed state):
> Internal review of the member listener (milestone 11 step 9): admission from the log, request refusals, connection and time bounds, the peer book, discovery, and the Linux firewall action hold against unauthenticated LAN peers, removed and quarantined devices, and endpoint redirection. Any LAN host that connects still receives a member's stable TLS certificate, so a listener can be linked across hours and networks until a membership proof precedes the server certificate. An admitted member can still degrade availability, by exhausting the authenticated connection budget or by reporting false endpoints, but cannot read or redirect data.
